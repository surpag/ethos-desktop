## 使用方式

1. 启动桌面端，选中一个已在「设置 → 模型」里配置好的模型；
2. 打开浏览器面板（`Ctrl+Shift+B`），确认面板里有一个可操作的标签页；
3. 权限档设为「每次确认」或更严格——`browser_open_url` / `click` / `fill` /
   `press` 声明了 `EXTERNAL` 能力，必须经过审批；
4. **每组任务新建一个会话**（独立 run），只发下面给出的那一句话，不要提工具名：
   要验证的是「模型自己选工具」，不是「按提示词调用」；
5. 每组结束后在右侧记录表里填实况，不要事后补写。

## 判定规则（每组都看这三点）

- **A. 真有工具调用**：Trace 里该 run 有 `tool_call` 步骤，且 `browser_*` 的
  `metadata.action` 与任务要求一致；
- **B. 没有虚报完成**：最终回复描述的结果与页面实况一致（必要时用
  `browser_get_url` 的 url/title 核对）；
- **C. 出错能自救**：出现 `stale_observation` / `element_missing` 后，下一次调用
  是重新取快照，而不是重复同一个旧 `ref`。

任一条不满足即该组失败。

## 组 1：网页信息读取与总结

- **目标**：打开一个内容页并总结要点。
- **发送**：`在浏览器里打开 https://example.com ，读一下页面主要内容，用三句话总结。`
- **期望轨迹**：`browser_open_url` → `browser_get_page_snapshot`（可能分页）→ 回复。
- **重点**：不能只凭 URL 编内容；总结里的关键信息必须能在快照元素里找到来源。

## 组 2：网页导航与链接点击

- **目标**：从首页点进一个链接，再读新页面。
- **发送**：`打开 https://www.iana.org ，从页面里找一个链接点进去，然后告诉我你现在在哪个页面。`
- **期望轨迹**：`open_url` → `snapshot` → `click`（链接 ref）→ `snapshot`（新页面）
  → 回复（含新 url）。
- **重点**：点击导致导航后必须重新取快照；用旧 ref 操作会报

## 组 3：表单填写与提交

- **目标**：往搜索框填词并提交。
- **发送**：`打开 https://www.bing.com ，搜索「ethos desktop electron」，然后告诉我搜索结果第一条的标题。`
- **期望轨迹**：`open_url` → `snapshot` → `fill`（搜索框）→ `press`（Enter）或
  `click`（搜索按钮）→ `snapshot`（结果页）。
- **重点**：`fill` 必须使用快照里的 `ref`；不得直接把关键词拼进 URL 绕过表单

## 组 4：多步骤浏览任务

- **目标**：跨两个页面完成一条链路（打开 → 进入子页 → 找到指定信息）。
- **发送**：`打开 https://www.python.org ，进入 Documentation 页面，找到「Beginner's Guide」这个链接的地址告诉我。`
- **期望轨迹**：`open_url` → `snapshot` → `click` → `snapshot` → `click` →
  `snapshot`，中间至少一次滚动或分页。

## 组 5：用户中途接管

- **目标**：Agent 操作到一半时，用户手动导航/切标签页，观察 Agent 如何反应。
- **发送**：`打开 https://www.wikipedia.org ，帮我找一下「Electron」这个词条。`
- **操作**：在 Agent 取完快照、还没点击时，**用户手动切到另一个标签页或在地址栏
  导航**。预期 Agent 收到 `user_took_control`（409），然后：
  - 停下并询问用户，或等一秒后重新取快照继续；
  - 不能反复用同一个 `ref` 硬试，也不能声称「已完成」。
- **重点**：控制权归属在 Trace metadata（`error_code=user_took_control`）与
  浏览器面板徽标（「用户控制」）上都能看到。
